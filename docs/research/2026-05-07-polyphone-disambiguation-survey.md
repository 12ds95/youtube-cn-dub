# 多音字消歧方案调研 (edge-tts 中文配音场景)

> 调研日期: 2026-05-07
> 触发: 用户反馈"了解被读成 liǎo (3声), 直觉被读成 jiào"
> 关联: `pipeline.py:_fix_polyphones`, `_POLYPHONE_HOMOPHONE_MAP`

## 背景

edge-tts 通过 SSML 的 `<voice>` + `<prosody>` 两个标签暴露能力, **不支持 `<phoneme>` 标签** (Microsoft 限制为 Edge 浏览器自身能生成的 SSML 子集), 因此中文多音字误读**只能在文本层面通过同音字替换修复**。

当前实现: `_POLYPHONE_HOMOPHONE_MAP` 用 13 个高频多音字 + pypinyin 短语级消歧, 当 pypinyin 判定的"正确读音"与 edge-tts 的"默认读音"不一致时, 替换为同音字 (例: `了`→`瞭` 强制读 liǎo)。

## 实测发现 (kCc 117 段)

| 多音字 | 替换次数 / 出现次数 | 替换正确率 (抽样) |
|---|---|---|
| 了 | 4/121 (3.3%) | 50% (4 例 2 错: "构成了"/"查看了" 应读 le 但被改成 liǎo) |
| 行 | 6/248 (2.4%) | 待人工抽查 |
| 重 | 14/63 (22.2%) | 待人工抽查 |
| 调 | 10/41 (24.4%) | 待人工抽查 |
| 应 | 21/79 (26.6%) | 待人工抽查 |
| 处 | 79/146 (54.1%) | 待人工抽查 |
| 量 | 5/159 (3.1%) | 待人工抽查 |
| 数 | 2/281 (0.7%) | 待人工抽查 |
| 率/传/的/差 | 0 | (未触发) |

**核心问题**: pypinyin 短语级消歧在 "动词+了+名词" 类语境下偶尔把 le 误判为 liǎo (如 "构成了"/"查看了"). 这是 pypinyin 公认的 ~87% 准确率短板, 不是当前代码 bug, 但影响显著 (kCc 上对"了"的替换正确率只有 50%).

**漏字问题**: `_POLYPHONE_HOMOPHONE_MAP` 不包含 `觉` / `为` / `好` / `和` / `得` 等高频陷阱字。例如用户报的"直觉" → "直 jiào" 是 edge-tts 自身误读 (默认 jiào), 当前代码完全未处理。

## 候选方案矩阵

| 方案 | CPP 数据集准确率 | 安装大小 | 推理速度 | 改动量 | 适合度 |
|---|---|---|---|---|---|
| **A. pypinyin + jieba 词级守卫** | ~95%* | 0 (已有) | ★★★★★ | ~50 行 | ✅ 最小 |
| **B. pypinyin-g2pw 直接替换** | **99.08%** | ~450 MB (BERT base + ONNX) | ★★ (BERT 单次 ~50ms) | ~10 行 | ⚠️ 重 |
| **C. g2pM (轻量 BiLSTM)** | ~97% | ~30 MB | ★★★ (~10ms) | ~30 行 | ✅ 平衡 |
| D. 混合 (pypinyin 默认 + g2pW 兜底特定字) | ~98% | ~450 MB | ★★★ (大多走 pypinyin) | ~80 行 | ⚠️ 复杂 |
| E. cpp-pinyin (C++ binding) | 90.3% | 中 | ★★★★ | 需 binding | ❌ 部署难 |
| F. PaddleSpeech frontend | 99%+ | 1 GB+ | ★★ | 大 | ❌ 太重 |

*A 估算: 当前 87% × 高频陷阱字白名单守卫 → 实测 5 个具体陷阱 ("了" / "为" / "好" / "和" / "得") 加守卫后逼近 95%

## 跨源验证

### 准确率数据 (跨源 1: g2pW 论文)
- g2pW 在 CPP dataset 上 99.08% test accuracy
- pypinyin baseline 在同 dataset ~87%
- g2pM (BiLSTM) ~97%
- cpp-pinyin (lightweight C++) ~90.3%

来源: [g2pW INTERSPEECH 2022](https://www.isca-archive.org/interspeech_2022/chen22d_interspeech.html), [cpp-pinyin README](https://github.com/wolfgitpr/cpp-pinyin)

### edge-tts 限制 (跨源 2: rany2/edge-tts maintainer)
> Support for custom SSML was removed because Microsoft prevents the use of any SSML that could not be generated by Microsoft Edge itself. The service only permits a single `<voice>` tag with a single `<prosody>` tag inside it.

来源: [edge-tts issue #58](https://github.com/rany2/edge-tts/issues/58)

### "了" 误判常见性 (跨源 3: pypinyin 用户反馈)
- pypinyin 4.10 后准确率 85-88% (修正了之前包含 unk/pad 的统计)
- "了" 在 `heteronym=True` 时显示为 `['le', 'liǎo', 'liào']`, 默认无 heteronym 时单字会落到 phrase-dict, 但短语 dict 不能 cover 所有上下文
- 推荐用 `load_phrases_dict` 自定义 (但维护负担重)

来源: [pypinyin 用法及短板讨论 (CSDN)](https://blog.csdn.net/qq_21201267/article/details/123521720), [pypinyin 简介 (知乎)](https://zhuanlan.zhihu.com/p/76597038)

### 参考项目 (跨源 4: 同类视频配音项目)
检查 `~/Desktop/VideoLingo` 与 `~/Desktop/pyvideotrans`:
- VideoLingo 仅在 `core/tts_backend/estimate_duration.py` 用 pypinyin **算时长**, 未做多音字修正
- pyvideotrans 不处理多音字
- 两者都接受 edge-tts 原始误读

**结论**: 同类社区项目对此问题缺位, 我们当前的 `_fix_polyphones` 已超出社区基线, 但仍受 pypinyin 87% 准确率限制。

### 工业界做法 (跨源 5: PaddleSpeech)
- PaddleSpeech 中文 frontend 默认用 `g2pM` + pypinyin 组合 (g2pM 优先, pypinyin 兜底)
- 路线图: 后续切换到 BERT-based (即 g2pW)

来源: [PaddleSpeech 中文 frontend doc](https://paddlespeech.readthedocs.io/en/latest/tts/zh_text_frontend.html)

## 学术基线 (BERT-based 方法概览)

- **Polyphone BERT** (arxiv 2207.12089): 把多音字映射到新单音字 (例 `泊1`/`泊2`), 然后微调 BERT 预测哪个单音字
- **External Knowledge Augmented LLM** (arxiv 2312.11920): 用 LLM + 词典外部知识做长尾消歧
- **Decoupled Learning Model** (NAACL 2024): 解决长尾多音字数据不平衡

但这些都是"研究级"方案, 需要训练数据 + GPU; 工业落地仍以 g2pW/g2pM 为主流。

来源: [Polyphone BERT (arxiv)](https://arxiv.org/abs/2207.12089), [LLM polyphone (arxiv)](https://arxiv.org/html/2312.11920v1)

## 推荐方向

按风险递增:

1. **A (pypinyin + jieba 词级守卫 + 补漏字)** — 0 新依赖, 改动小, 实测 5 个陷阱字补完后预期到 95%+
2. **C (g2pM 轻量 BiLSTM)** — 30 MB, 推理快, 工业默认方案 (PaddleSpeech 在用)
3. **B (pypinyin-g2pw)** — 450 MB BERT, 99% 准确率, 一劳永逸但重

本项目场景: 视频配音, 不在意 TTS 阶段额外几秒推理 (相比已经几十分钟的 LLM 翻译), 但**部署轻量** + **冷启动快**有价值。

→ 选定路径: **A 先做 → 验证不够再升 C**
